
Hệ thống mô phỏng lỗ hổng Web Cache Poisoning được thiết kế theo mô hình client - server, trong đó người dùng tương tác qua trình duyệt (client) và gửi các yêu cầu HTTP tới máy chủ (server):
 
Trong mô hình, Client đại diện cho trình duyệt hoặc công cụ gửi yêu cầu HTTP/HTTPS (bao gồm cả người dùng hợp lệ và tác nhân kiểm thử). Các yêu cầu từ Client được truyền qua Internet để phản ánh bối cảnh truy cập từ bên ngoài vào hệ thống, đồng thời thể hiện đặc trưng “chia sẻ” của bộ nhớ đệm khi nhiều người dùng cùng truy cập một tài nguyên. Thành phần Reverse Proxy đóng vai trò trung gian nằm giữa Client và máy chủ gốc, thực hiện tiếp nhận request, áp dụng các chính sách cache và chuyển tiếp request đến Web Server khi cần thiết. Trong trường hợp cache hit, Reverse Proxy/CDN có thể trả về phản hồi đã được lưu trước đó mà không cần truy vấn về máy chủ gốc; ngược lại, khi cache miss, request sẽ được chuyển tiếp đến Web Server để tạo phản hồi mới và phản hồi này có thể được lưu lại trong cache tùy theo cấu hình.
Web Server là máy chủ origin chịu trách nhiệm xử lý request và sinh response dựa trên tài nguyên yêu cầu cũng như các thành phần đầu vào của request (URL path, query parameter, header, cookie,…). Điểm quan trọng trong các kịch bản Web Cache Poisoning là sự khác biệt giữa cách Reverse Proxy xây dựng cache key và cách Web Server sử dụng đầu vào để tạo nội dung phản hồi. Nếu một thành phần đầu vào ảnh hưởng đến response nhưng không được đưa vào cache key, phản hồi tạo bởi request “độc” có thể bị lưu trong cache và được phát lại cho những người dùng khác truy cập cùng tài nguyên. Do đó, mô hình trên là nền tảng chung để triển khai các kịch bản thực nghiệm trong các mục tiếp theo của chương.
Về ngôn ngữ lập trình: ứng dụng web được phát triển bằng PHP, một ngôn ngữ lập trình phía máy chủ phổ biến trong việc xây dựng các hệ thống web động. Trong kiến trúc triển khai, Nginx đóng vai trò là web server và reverse proxy, tiếp nhận các yêu cầu HTTP từ phía client và chuyển tiếp đến tiến trình xử lý PHP thông qua PHP-FPM. 
Về giao diện, hệ thống sử dụng HTML kết hợp với CSS để tạo ra một giao diện đơn giản, hỗ trợ tốt cho quá trình tương tác giữa người dùng và hệ thống
Về môi trường triển khai, toàn bộ hệ thống được đóng gói dưới dạng các container riêng biệt sử dụng Docker, với công cụ Docker Compose để quản lý đa container. 
Để kiểm thử và phân tích các lỗ hổng bảo mật: công cụ chính được sử dụng là Burp Suite (phiên bản Professional). Burp Suite cho phép theo dõi và chỉnh sửa các gói tin được gửi giữa client và server, từ đó giúp phát hiện và khai thác lỗ hổng một cách trực quan và chính xác.
